# Required tests for the publish-gating Postgres + all-features lane.
#
# The lane (`scripts/run-nextest-shards.sh`, task `nixTestLocal`, a
# dependency of `publishContainerImage`) runs every workspace lib and
# integration test with `--all-features` (so `clustering`) against a real
# Postgres, with WADDLE_TEST_REQUIRE_POSTGRES=1 so a test that finds no
# database panics instead of returning early as a pass. It then reads the
# executed test names from each shard's nextest JUnit report
# (`scripts/check_required_tests.py`) and fails, blocking publish, if any test
# below did not execute or did not pass. The executed names are saved as
# `.ci/nextest-archive/executed-tests.txt` in the lane's diagnostics artifact
# (uploaded on PRs always, on main only when the lane passes); on failure the
# missing names and the executed names of their binaries are printed to the
# job log. A test nextest reports as flaky (passed on retry) counts as failed;
# the `ci` profile sets `retries = 0`, so keep that coupling in mind before
# adding retries.
#
# FORMAT: one test per line, `<binary-id> <test-name>`, separated by
# whitespace, exactly as `cargo nextest list --workspace --all-features`
# prints them. `#` starts a comment; blank lines are ignored; duplicates and
# lines with other than two fields are rejected.
#   Integration test (crates/<crate>/tests/<file>.rs):
#     waddle-server::clustering_cluster_e2e lone_survivor_and_isolation_fencing
#   Library unit test (#[cfg(test)] module inside crates/<crate>/src): the
#   binary id is the bare crate name and the name is the module path:
#     waddle-server ingress::xep0045_room_manifest_tests::postgres_clustered_dark_manifest_remains_authoritative_without_test_opt_in
#     waddle-xmpp mam::storage::sqlx_store::tests::postgres_backend_exposes_only_postgres_pool
#
# TO ADD TESTS: append a block at the end of the file headed by a comment
# naming the slice/issue and why the tests must run before an image ships.
# List tests whose omission would invalidate the publish evidence. Listing a
# test checks that it ran and passed; it does not alter which tests run or
# suppress failures. Track and fix flakes separately.
#
# Exclusions:

#     #[ignore]d manual measurement; never runs in CI.
