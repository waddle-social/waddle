# Postgres-backed tests that may run outside nextest's `postgres` test group.
#
# Every test listed here uses only a per-test UUID-suffixed schema or a
# per-test database. Schema-isolated tests run against their schema via
# search_path and never reset or alter shared application tables. Database-
# isolated tests also have a private PostgreSQL advisory-lock namespace. Tests
# that assert availability of database-wide locks stay in the `postgres`
# group, even when their application tables use a unique schema. A fixture
# shared by many concurrent tests that runs migrations or store bootstrap
# needs a per-test database: those paths take the database-scoped catalog
# mutation fence with a bounded try-lock, which a unique schema still shares.
# scripts/check_postgres_test_group.py requires every other Postgres-backed
# test to match the group filter in .config/nextest.toml, and fails on entries
# here that no longer need listing.
#
# Format: one entry per line, relative to server/. `#` starts a comment.
# - `<file>`: every Postgres-backed test declared in that file is isolated.
# - `<file>::<Type or module>::<fn>`: a fixture that always creates and uses
#   its own uniquely named schema; tests whose only route to the database is
#   that fixture need no entry of their own, wherever they are declared
#   (including through `include!`).
