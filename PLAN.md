# Plan: AI Channel Search via XMPP-Native Tool Use

## Problem

The AI bot hardcodes context access (last 20 MAM messages pre-fetched before every prompt).
It can't search history, can't reach beyond the last 20 messages, and can't be extended
without server code changes. The WIT extension interface has no concept of AI tools.

## Goal

- AI gets channel history via proper **function calling** (OpenAI tool use protocol)
- Extensions declare tools in the WIT manifest — no server code changes needed for new tools
- Built-in tools (MAM search, recent messages) live server-side since they need DB access
- `AiToolRequest::Extension` variant routes unknown tool names to the extension that registered them

---

## Architecture

```
User: /ai @randax what was he working on?
  │
  ▼
ai-chatbot WASM extension
  → BotGroupchatResponse(fallback)
  │
  ▼
interpret.rs (DispatchToRoom handler)
  → build tool list: built-in tools + extension tool definitions
  → RoomToolExecutor { mam_storage, room_jid, extension_manager }
  → generate_ai_response(prompt, &tools, executor)
  │
  ▼
generate_openai_compatible_response loop (MAX 5 rounds)
  → POST /v1/chat/completions with tools=[search_channel_history, get_recent_messages, <ext tools>]
  │
  ├── finish_reason: "stop"  → return answer
  │
  └── finish_reason: "tool_calls"
        → for each tool call:
            "search_channel_history" → RoomToolExecutor → MAM fulltext query
            "get_recent_messages"    → RoomToolExecutor → MAM last-page query
            "<extension tool>"       → RoomToolExecutor → ExtensionManager.dispatch_tool_call()
                                           → WASM: handle_event(ToolCall { id, name, args })
                                           → WASM returns: ToolResult { id, content }
        → POST with tool results → loop
```

## Changes

### 1. `server/wit/waddle-extension.wit`

Add to `interface types`:

```wit
// A tool the extension exposes to the AI.
record tool-definition {
    name: string,
    description: string,
    parameters-schema-json: string,  // JSON Schema object as a serialized string
}

// Inbound: AI wants to call a tool registered by this extension.
record tool-call-context {
    call-id: string,
    tool-name: string,
    arguments-json: string,
}

// Outbound: extension result for a tool call.
record tool-call-result {
    call-id: string,
    content: string,
}
```

Add `ai-tool` to `enum extension-capability`.

Add `tool-call(tool-call-context)` to `variant extension-event`.

Add `tool-result(tool-call-result)` to `variant extension-effect`.

Add `tools: list<tool-definition>` to `record extension-manifest`.

### 2. `server/crates/waddle-extensions/` (extension manager)

- Add `Rust` mirror types for `ToolDefinition`, `ToolCallContext`, `ToolCallResult`
  (generated by `wit-bindgen` like the existing types).
- Add `ExtensionManager::collect_ai_tools() -> Vec<(PluginId, ToolDefinition)>`
  — returns all tools declared in loaded extension manifests.
- Add `ExtensionManager::dispatch_tool_call(tool_name, call_id, arguments_json) -> Option<String>`
  — routes to the extension that registered the tool; returns tool result content or error string.

### 3. `server/crates/waddle-server/src/ai_provider.rs`

**Remove:**
- Hardcoded `tool_definitions()` (no longer static)
- `history: &[HistoricalMessage]` parameter from all public functions

**Add:**
- `pub enum AiToolRequest` with variants:
  - `SearchChannelHistory { query: String, max: Option<u32> }`
  - `GetRecentMessages { max: Option<u32> }`
  - `Extension { name: String, arguments: serde_json::Value }` — for WASM extension tools
- `pub enum AiToolResult { Messages(Vec<HistoricalMessage>), Error(String) }`
- `pub trait AiToolExecutor: Send + Sync` with `async fn execute(&self, AiToolRequest) -> AiToolResult`
- `pub struct NoopToolExecutor` — returns `Error("unavailable")` for everything
- `pub fn builtin_tool_definitions() -> Vec<serde_json::Value>` — search + recent tools
- Update `generate_ai_response(prompt, tools, executor)` — takes dynamic tool list
- Update `generate_ai_response_with_config(client, config, prompt, tools, executor)` — same
- `parse_tool_request`: unknown tool names → `AiToolRequest::Extension { .. }` (not `Err`)

**Update tests** to use `NoopToolExecutor` and add tests for:
- Tool definitions present in every request
- Tool call loop: model calls tool → executor fires → result sent back → final answer
- `Extension` variant routed correctly (mock executor returns expected content)
- `NoopToolExecutor` returns error content to model (model can still answer gracefully)

### 4. `server/crates/waddle-server/src/server/routes/interpret.rs`

**Remove:** `fetch_room_history_for_ai` function (entire block, ~50 lines).

**Add:** `RoomToolExecutor` struct + `AiToolExecutor` impl:

```rust
struct RoomToolExecutor<'a> {
    mam_storage: &'a dyn MamStorage,
    room_jid: &'a BareJid,
    extension_manager: Option<&'a ExtensionManager>,
}

// execute():
//   SearchChannelHistory  → mam_storage.query_messages(fulltext query)
//   GetRecentMessages     → mam_storage.query_messages(last-page query)
//   Extension { name, .. }→ extension_manager.dispatch_tool_call(name, id, args)
//                           returns AiToolResult::Error if no extension manager
```

**Update call site** (currently calls `generate_ai_response(prompt, &room_history)`):

```rust
let builtin = ai_provider::builtin_tool_definitions();
let ext_tools = deps.extension_manager
    .map(|em| em.collect_ai_tools())
    .unwrap_or_default();
let all_tools: Vec<_> = builtin.iter().chain(ext_tools.iter()).cloned().collect();

let executor: Box<dyn AiToolExecutor> = if let Some(mam) = deps.mam_storage {
    Box::new(RoomToolExecutor { mam_storage: mam.as_ref(), room_jid: &room_jid, extension_manager: deps.extension_manager })
} else {
    Box::new(NoopToolExecutor)
};

match generate_ai_response(prompt, &all_tools, executor.as_ref()).await { ... }
```

**Add tests** in the existing `#[cfg(test)]` block:
- `RoomToolExecutor::SearchChannelHistory` uses MAM fulltext query
- `RoomToolExecutor::GetRecentMessages` uses MAM last-page query
- `Extension` variant without extension manager returns error

### 5. `server/extensions/ai-chatbot/src/lib.rs`

No changes required for this PR. The WIT additions are backwards-compatible (new
optional fields in manifest, new variants the extension ignores). A follow-up PR
will update `ai-chatbot` to declare its own tools if desired.

### 6. Tests / XEP coverage

- `ai_provider.rs` gets new tests (already listed above)
- `interpret.rs` gets `RoomToolExecutor` unit tests
- `server/crates/waddle-xmpp/tests/xep0431_fulltext_search.rs` — new dedicated
  test file for XEP-0431 channel search (covers `MamStorage::query_messages` with
  fulltext filter end-to-end, per the CLAUDE.md XEP test-suite hard rule)

## What this PR does NOT do

The following are left for follow-up PRs (noted in the PR description):
- Roster / member list tool
- Space / channel listing tool
- Send-message tool (DMs and rooms)
- Actually updating `ai-chatbot` extension to use `ExtensionCapability::AiTool`
- Any UI changes in `chat/`
