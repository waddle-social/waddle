## Conditional differences around shared keys

1. **Actor construction.** The shared `UserActor::new` call constructs extra state under `any(test, feature = "test-utils")`: a synthetic claim identity, bounded diagnostic journal, and overflow counter ([implementation.rs:50](../../../server/crates/waddle-xmpp/src/registry/user_actor/implementation.rs#L50)). The identity is a fixture label, not an acquired distributed claim ([implementation.rs:42](../../../server/crates/waddle-xmpp/src/registry/user_actor/implementation.rs#L42)). The same marker therefore need not represent the same constructed state.

2. **Actor registration.** The shared path attempts to seal a prior actor binding if one exists, ignores the seal result, then inserts the connection ([implementation.rs:212](../../../server/crates/waddle-xmpp/src/registry/user_actor/implementation.rs#L212)). With test-utils, guarded reads capture previous/candidate identity and attempt a bounded binding snapshot only while journal capacity remains; a diagnostic observation is appended afterward only below that capacity, otherwise the overflow counter is incremented ([implementation.rs:203](../../../server/crates/waddle-xmpp/src/registry/user_actor/implementation.rs#L203), [implementation.rs:216](../../../server/crates/waddle-xmpp/src/registry/user_actor/implementation.rs#L216)). The journal explicitly lacks endpoint-publication, claim-authorization, custody and teardown receipts ([user_actor.rs:105](../../../server/crates/waddle-xmpp/src/registry/user_actor.rs#L105)); do not classify the journal as authority or omit the real adjacent mutation.

3. **Bind lock.** Under test-utils the shared bind-slot lookup is followed by an explicit polling wrapper around `slot.lock_owned()`, which removes and signals an armed pending-bind probe only if a poll is pending ([binding.rs:244](../../../server/crates/waddle-xmpp/src/registry/connection_registry/binding.rs#L244)); without the feature the same lock future is awaited directly ([binding.rs:258](../../../server/crates/waddle-xmpp/src/registry/connection_registry/binding.rs#L258)). This adds a conditional observation side effect and polling path; source alone does not establish that a probe was armed or that lock serialization changed.

4. **Actor endpoint custody and retirement.** The shared custody seal is conditional on successful binding seal and an actor queue ([endpoint.rs:288](../../../server/crates/waddle-xmpp/src/registry/connection_registry/endpoint.rs#L288)). A new `test-support` caller, `publish_binding`, attempts to seal its exact candidate on spawned publication error or an undeliverable result ([actor_local_endpoint.rs:1020](../../../server/crates/waddle-server/src/server/routes/websocket/actor_local_endpoint.rs#L1020), [actor_local_endpoint.rs:1057](../../../server/crates/waddle-server/src/server/routes/websocket/actor_local_endpoint.rs#L1057)); the candidate delegates through [outbound.rs:1006](../../../server/crates/waddle-xmpp/src/registry/connection_registry/outbound.rs#L1006) and [outbound.rs:591](../../../server/crates/waddle-xmpp/src/registry/connection_registry/outbound.rs#L591) to that shared seal. The same failure path also calls `PublicationTicket::retire`, whose shared marker at :221 attempts exact provisional-candidate removal and asks for owner-qualified mirror removal; an error may return before asynchronous retirement completes ([actor_local_endpoint.rs:216](../../../server/crates/waddle-server/src/server/routes/websocket/actor_local_endpoint.rs#L216)). Preflight failures may return before spawned cleanup. The owner is release compiled but [not selected by `/ws`](../../../server/crates/waddle-server/src/server/routes/websocket/actor_local_endpoint.rs#L1); feature-on caller availability is not a live-cutover claim.

5. **Resume and endpoint handback.** Before the shared phase read, a `test-support` seam runs between publication and stream finalization ([registration.rs:835](../../../server/crates/waddle-server/src/server/routes/websocket/registration.rs#L835)). It returns immediately when disarmed or unmatched, when lifecycle is not running, or when no owner-matched entry exists ([characterization_seams.rs:235](../../../server/crates/waddle-server/src/server/routes/websocket/characterization_seams.rs#L235)); when configured and matched it may reserve old-binding capacity or attempt to enqueue a frame ([characterization_seams.rs:265](../../../server/crates/waddle-server/src/server/routes/websocket/characterization_seams.rs#L265)), wait for release and inject a replay gap ([characterization_seams.rs:326](../../../server/crates/waddle-server/src/server/routes/websocket/characterization_seams.rs#L326)). If exact owner lookup, seal, unregister and binding match succeed with a supplied receiver, and a frame is accepted and remains queued, the unchanged receiver-empty proof at [endpoint.rs:318](../../../server/crates/waddle-xmpp/src/registry/connection_registry/endpoint.rs#L318) fails at the shared handback call; the failed-resume logic can then mark handoff blocked ([stream_management/registration.rs:398](../../../server/crates/waddle-server/src/server/routes/websocket/stream_management/registration.rs#L398)). An attempted send or gap injection is not proof that either succeeded.

6. **Writer reachability.** A `test-support` branch before the shared `live_resume_control` send can call an SM-enable hold and return `TransportClosed` on `Refused`, before reaching the send ([batch_write.rs:459](../../../server/crates/waddle-server/src/server/routes/websocket/batch_write.rs#L459)). It requires a binding permit and pending enable commit. The hold normally continues without its directory environment variable, but configured setup errors or timeout can refuse ([characterization_seams.rs:519](../../../server/crates/waddle-server/src/server/routes/websocket/characterization_seams.rs#L519), [characterization_seams.rs:558](../../../server/crates/waddle-server/src/server/routes/websocket/characterization_seams.rs#L558)). Feature-on does not itself prove the seam was armed, that the send was reached, or that a frame was attempted.
