# Tenant isolation and inference credentials

## Release decisions

Deploy one independently operated, replicated credential broker per trust domain in its own namespace and secret store. Give it a distinct workload identity, database permissions, network policy and KMS permissions. Cells share the service. Start with a shared cell pool and support assigning a tenant to a dedicated cell with the same binary and placement contract. Keep reviewed, pinned first-party Wasm components in the server process for this release. Require a separately confined extension host before accepting third-party components. Use tenant credentials for unattended work. User credentials require an explicit invocation by a local account, scoped consent, and an allowed provider. Never silently switch the payer when any check fails.

Model both storage and authorization behind backend-agnostic traits so deployments can run self-hosted **Turso + OpenFGA** (the primary multi-tenant target: one self-hosted `tursodatabase/turso` database and one OpenFGA `store_id` per tenant on a shared OpenFGA cluster) or **PostgreSQL + SpiceDB** without changing cell, broker, placement or guest contracts:

- **Storage traits** (`TenantStore`, `PlacementLeaseStore`, `AdmissionLedgerStore` behind `server/crates/waddle-server/src/db/`): implement for self-hosted **Turso** (`turso` Rust engine in WAL mode, one `.db` per tenant) and **PostgreSQL** (`tenant_id`-scoped schemas/rows with restricted runtime roles).
- **Permission trait** (`PermissionBackend` replacing the closed `PermissionActorBackend` enum in `server/crates/waddle-server/src/permissions/actor.rs`): implement for **OpenFGA** (per-tenant `store_id`, pinned `authorization_model_id`, `HIGHER_CONSISTENCY` reads, and OpenFGA Access Control with Modular Models) and **SpiceDB** (`FullyConsistent` reads with schema/codec incarnation guards), plus the local test backend.

This plan covers the tenancy and credential addendum. Its numbered steps are delivery order. Supersede the host-AI prohibition in `server/docs/rfcs/0007-ai-integrations.md` and `server/docs/rfcs/0014-bot-framework.md` via an ADR for brokered typed inference. The proposed tenant placement lease must compose with or replace `ClaimStore` (`server/crates/waddle-server/src/clustering/claims.rs`) and `EPOCH_GUARDED_TABLES`. The current [keypair-slot lease](https://github.com/waddle-social/waddle/blob/main/server/crates/waddle-server/src/clustering/lease.rs) allocates node swarm identities; it does not establish tenant ownership.

## Security contract

Actors, scoped types and quotas contain ordinary mistakes and overload. A compromised cell can read or change application data available to its process, falsify cell-owned transcript selection or room membership (`chat` module tuples), and abuse its assigned tenants' permitted unattended operations within broker limits. Dedicated placement reduces that exposure only if storage mounts/handles, OpenFGA store grants, backups and service identities enforce the same boundary. Provider keys must appear in plaintext only at the enrolling client, the broker and the selected provider. Broker compromise has a larger blast radius. Isolate its namespace and secret vault (`SecretStore`, never a shared `ClusterSecretStore`), restrict its administrators, egress and KMS grants, and audit their use independently.

Authenticate cells and brokers with short-lived SPIFFE/SPIRE X.509 identities over mutual TLS. Because standard Kubernetes workload attestation assigns one SPIFFE ID per cell role/ServiceAccount, bind each process incarnation's ephemeral keypair to the mTLS channel (for example via RFC 9266 `tls-exporter` proof of possession) so a stale replica sharing the role cannot impersonate the new leaseholder.

Prove user and admin intent independently of cells. Today cells terminate OIDC (`Colony`), mint `sessions` with `WADDLE_SESSION_KEY`, verify `native_users` SCRAM, and evaluate `serverOwnerLocalparts`/`pubsub_affiliations`. Member-funded calls require a registered client device signing key and a single-use signed command bound to the operation. Device-key enrollment, account recovery, consent, credential replacement and administrative policy changes must carry an independently verifiable IdP proof (such as a `Colony`-signed JWT or WebAuthn assertion binding challenge, audience and client public key) inside the XMPP payload, verified directly by the broker against IdP JWKS. Cell-local SCRAM accounts (`native_users`) and cell-asserted admin flags are ineligible for member-funded credentials or broker policy mutations. Pin a root broker-key-signing public key in trusted client builds (`chat/`, Apple, Android, Linux) to authenticate rotatable broker encryption subkeys delivered in-band over XMPP without introducing out-of-band HTTP APIs. Gate member-funded release on this trust path; until then, ship tenant-funded inference only. Even a genuine command cannot attest room data later supplied by a compromised cell; require a client-approved payload digest or an independent trusted content reader before promising exact payload integrity.

## Implementation sequence

1. **Pin trait contracts, storage topology and the feasibility spike.** Inventory the cell, ingress authentication, IdP (`Colony`), storage (`Turso` and `PostgreSQL`), authorization (`OpenFGA` and `SpiceDB`), broker, KMS (Scaleway Key Manager or isolated Vault Transit), client and provider trust boundaries. Assign ownership for placement writes, consent writes, device enrollment, key destruction and provider qualification. Define measurable request, token, byte, file-descriptor, latency and cancellation bounds before rollout.

   Resolve the self-hosted `tursodatabase/turso` multi-pod topology up front: because `turso` is an in-process file engine (not networked `libsql-server`), choose and test either (a) a thin mTLS-authenticated Turso storage-host service enforcing `(tenant_id, holder_id, placement_generation)` on every query/batch, or (b) RWO Mayastor shard volumes per active holder with fenced S3/R2 WAL handoff—applying the same explicit choice to the replicated broker ledger (tenant-sharded Turso `.db` ownership vs. a shared HA PostgreSQL backing store alongside OpenFGA). Verify `server/crates/waddle-server/sql/baseline/sqlite.sql` (including FTS5 MAM search, triggers and millisecond `unixepoch('subsec') * 1000` timestamps) on the pinned `turso` crate in standard WAL mode (do not rely on pre-1.0 `PRAGMA journal_mode=mvcc`). Build a disposable two-cell, two-broker native fixture (extending `server/experiments/native-fixture` with no containers) exercising both `(Turso + OpenFGA)` and `(Postgres + SpiceDB)` implementations: demonstrate bounded streaming through the WIT guest interface, workload rotation, denial after lease transfer (including two replicas sharing one cell role), authenticated sealed enrollment and secret-free telemetry. Record results and resolve trust-boundary failures before building the feature.

2. **Make tenant scope and backend traits structural.** Define a canonical `TenantId` from verified local domain routing and use a tenant registry as the sole constructor of actor, cache, `TenantStore` and `PermissionBackend` handles. Introduce an immutable `account_id` UUID across `users` and `native_users` so encryption AAD and authorization subjects never depend on mutable localparts. Scope in-memory registries (`RoomRegistryActor`, `ConnectionRegistry`, `CommandRegistry`, `ExtensionManager`, federated `BareJid` caches where `alice@remote.example` can join multiple tenants) and fix `WasmExtensionActor` (`actor.rs`), which currently hardcodes `waddle_id = "local"`.

   For the **Turso** `TenantStore` implementation, isolate each tenant in its own `<tenant>.db` file behind a bounded LRU handle/FD pool (checkpointing and closing idle databases within `RLIMIT_NOFILE`) and scope `auth_identities` per tenant database. For the **PostgreSQL** `TenantStore` implementation, require `tenant_id` in persistent keys, unique constraints (`users`, `auth_identities`, `spaces_metadata`), joins, invalidation, queues and job envelopes, keeping `baseline.rs` schema-catalog parity intact. Add a narrow lexical/type architecture guard (modeled on `server/scripts/check-ingress-typed-entry.py`) plus same-localpart/different-tenant and same-remote-`BareJid`/different-tenant contract tests running against both storage backends. Bound mailboxes, tasks, outstanding streams, Wasm linear memories (`memories * memory_bytes` in `runtime/host_state.rs`, which currently allows `4 * memory_bytes` per unpooled store), Wasm fuel, wall-clock interruption and database concurrency per tenant behind explicit semaphores before instantiation. Reserve capacity for lease heartbeats and cancellation.

3. **Establish placement and dispatch fencing across storage backends.** Implement `PlacementLeaseStore` for both Turso and PostgreSQL, storing `tenant_id`, assigned cell role, channel-bound `holder_instance` (mTLS identity + incarnation key proof), monotonic `generation`, authoritative lease expiry (`now()` on Postgres; primary `CAST(unixepoch('subsec') * 1000 AS INTEGER)` on Turso, never client or embedded-replica clocks) and transfer state. Use durable compare-and-set for claim, renewal, transfer and release. A stale holder cannot acquire the current holder's identity through a request field. Fence tenant data writes, background tasks (`room_observation`, push/outbox workers) and multi-step `CommandRegistry` state at their owning stores as well as broker admission: on PostgreSQL via `FOR SHARE`/epoch-guarded `EnteredTransaction`, and on Turso via storage-host generation checks or RWO PVC + fenced WAL manifest handoff. Implement shared and dedicated placement, including quiescing within `WADDLE_DRAIN_TIMEOUT_SECS`, handoff and crash reclaim. Test lease expiry, suspend-aware boot clocks (`BootInstant`), clock skew, partition, duplicate claim and same-role cell races on both backends.

4. **Deploy broker custody and the credential lifecycle.** Use authenticated envelope encryption (AES-256-GCM or XChaCha20-Poly1305 with length-prefixed AAD binding trust domain, `tenant_id`, immutable `account_id` where applicable, provider, `credential_id` and version). Wrap per-user data keys under per-tenant data keys and keep tenant wrapping authority behind broker-only KMS access. Store only ciphertext and opaque metadata outside custody. Maintain a KMS-backed per-user wrapping secret or broker-owned destruction ledger enforced on every restore before reopening egress, since deleting rows alone leaves ciphertext in PostgreSQL WAL/basebackups and Turso S3/R2 WAL segments. Specify generation, rotation, replacement, withdrawal, account retirement (`retired_account_jids`), tenant deletion (including Turso file/WAL purge and OpenFGA `DeleteStore`) and recovery under documented retention deadlines. Run a restore drill verifying revoked keys, deleted users, old generations and restored authorization state stay unusable before reopening egress.

   Carry enrollment, status, rotation, revocation and policy operations over authenticated XMPP `<iq/>` stanzas using a versioned `urn:waddle:*` namespace (never `<message/>`, whose XEP-0334 hints are bypassed on bare/server JIDs, and never generic `extensions.<domain>` XEP-0050 forms, where client `isForbiddenExtensionCommandField` guards block secret fields; amend `docs/superpowers/plans/2026-04-27-waddle-extension-xmpp-protocol.md` and `docs/xep-conformance-audit.md` after reviewing `./xeps/` from `xsf/xeps`). Seal secrets on the client to a rotatable broker subkey signed by the client-pinned root trust anchor, binding owner `account_id`, `tenant_id`, provider, purpose, single-use nonce, expiry and version. Strip `urn:waddle:*` credential payloads on every IQ error-bounce path (`route_to_connection`, `destination`, `full_jid_forward`, `muc_admin`), never write unsealed secrets into client XEP-0198 `localStorage` (`PersistedSmResumeState`), and make broker enrollment nonces idempotent across automatic XEP-0198 reconnect replay while keeping outbound IQ results/errors opaque (since countable stanzas are persisted in `sm_unacked.stanza_xml`). Workload RPC, placement, KMS and authorization checks remain internal operations.

5. **Implement `PermissionBackend` (`OpenFGA` + `SpiceDB`) and a single fenced admission decision.** Implement the `PermissionBackend` trait for both **OpenFGA** and **SpiceDB** behind one domain model covering spaces, channels, messages, DMs, roles, tenant/user credentials, installed extensions and room inference policies:

   - **OpenFGA implementation**: Provision one `store_id` per tenant on the shared self-hosted OpenFGA service (backed by its own dedicated HA datastore), pin immutable `authorization_model_id`s, and enable OpenFGA Access Control (`--access-control-enabled`) with Modular Models (`schema 1.2`). Grant a cell's workload OIDC identity `writer` only on `module:<store_id>|chat` and `reader` on `store:<store_id>` for its currently leased tenants; grant **only** the broker/authz authority `writer` on `module:<store_id>|inference`. Use `consistency: HIGHER_CONSISTENCY` on every broker `Check` and reject caller-supplied `contextual_tuples`.
   - **SpiceDB implementation**: Scope object IDs by `tenant_id` within `MAX_AUTHZ_ID_BYTES` (`765` raw bytes), enforce `Consistency::FullyConsistent`, and isolate credential/consent writes behind an authz proxy or dedicated broker SpiceDB namespace coordinated with `AUTHZ_SCHEMA_VERSION`.

   Validate the device-signed invocation at the broker, binding `tenant_id`, `account_id`, installed extension/digest, `room`, provider, payer, command digest, expiry, single-use nonce and bounded spend. Issue a bounded run identifier for multi-turn tool rounds with explicit call/token budgets, unique step IDs and a single-use ledger. Observation, schedule, webhook and federated remote principals cannot select member credentials; keep tenant-funded use a separately authorized action.

   Implement `AdmissionLedgerStore` for both Turso and PostgreSQL. Because OpenFGA exposes no `ZedToken`, serialize revocation, room/community policy restriction and placement transfer against dispatch using **three** durable fence keys in the same ordering domain: `(tenant, credential)`, `(tenant, room_or_space)` and `(tenant, placement)`. On any restriction (including room kicks/outcasts or room AI-policy changes), close the affected fence first, advance its generation, apply the `PermissionBackend` or placement mutation, reconcile/abort affected dispatches via a short-tick broker `ReplicaFence` (modeled on `permissions/host_grant/fence.rs` so peer broker replicas cancel local in-flight streams), then acknowledge and reopen if applicable. On grant, publish permissions to `PermissionBackend` before opening admission. For dispatch, snapshot the three fence generations, run a fresh `PermissionBackend` check (`HIGHER_CONSISTENCY` / `FullyConsistent`), then in one atomic `AdmissionLedgerStore` transaction verify all three fences remain open at those exact generations, verify holder/expiry/budgets, reserve spend and claim a unique attempt ID. Fail closed on missing authority, stale generation or ambiguous recovery. Never retry an ambiguous billable send without provider-guaranteed request-key deduplication—explicitly updating `ingress_uow/room_observation/work.rs` so `unknown_after_send` quarantines work instead of bypassing `MAX_ATTEMPTS`. Replayed XMPP commands return existing status; reconcile reserved cost conservatively.

6. **Build constrained provider egress and the streaming guest contract.** Offer typed inference operations in `server/wit/waddle-extension.wit` (bumping from `waddle:extension@3.0.0`) with credential reference `tenant(name)` or `invoking-user(provider)`. Resolve owner and credential from the trusted invocation context; give guests neither bearer headers, raw config secrets (`runtime.get-config`), nor reusable credential IDs. Broker adapters construct outbound requests from an approved provider, deployment, model and exact operation, enforcing destination, DNS-resolved IP allowlists (blocking loopback/RFC1918/link-local/metadata SSRF), TLS identity, method, path, headers, `.no_proxy()`, disabled redirects, payload/output byte caps, deadlines, concurrency and spend. Never permit provider administration or credential inspection with a managed key. Validate response shapes and discard upstream headers and error bodies (removing `provider.rs`'s 512-byte error-body echo). On cells, remove `outbound.http.request` and `allowedHttpOrigins` from inference guests and route remaining legitimate cell HTTP egress through an explicit policy boundary.

   Add an invocation-bound WIT stream resource with bounded chunk reads, explicit terminal usage/outcome (replacing unverified guest-reported `invocation-usage`), bounded queues at every hop, and non-blocking upstream cancellation wired into synchronous Rust `Drop` on the host resource table entry (since `tokio::time::timeout` drops `Store<HostState>` without calling async WIT `drop`). Decouple streaming inference execution and progressive client delivery from the synchronous `15s` WebSocket `STANZA_HANDLER_WEDGE_TIMEOUT` (`frame_backstop.rs`) and unary XEP-0050 IQ replies, and coordinate stream cancellation with `WADDLE_DRAIN_TIMEOUT_SECS`. Narrow `wasmtime_wasi` linker imports in `runtime/loader.rs` from full `wasmtime_wasi::p2::add_to_linker_async` to only the WASI interfaces declared in `waddle-extension.wit`, and disable `inherit_stderr()` and guest log forwarding (`runtime/host_state.rs`) for inference invocations so prompts and outputs cannot leak to pod logs. Satisfy the spike with a guest that reads the first chunk before completion and cancels.

7. **Migrate both inference paths and enforce host-level room privacy.** Migrate `server/extensions/ai-chatbot` and `server/extensions/jev-judgments` off `Authorization` headers, `configSecretFiles` (`waddle-openrouter`) and free-form endpoints onto opaque broker references and reviewed provider profiles. Update `server/deployment.cue`, `server/observer-release.json` and the hardcoded `ai-chatbot` `api_key`/`allowedHttpOrigins` assertions in `server/charts/waddle-server/templates/validations.yaml` together. Inventory command forms, client rendering, storage, manifests, deployment inputs, logs and config exports; use sealed enrollment or a one-time broker-owned importer, rotate and invalidate every former provider key, scrub `extension_room_observers` secret-hash identities and live copies, document backup retention, and disable legacy builds accepting plaintext keys or direct egress.

   Start member-funded `/ai` with explicit room invocation and tightly bounded visible room text, reviewing tenant-funded `/ai` entry points before changing them. Enforce `InvocationContext.source_room` archive bounds in **host** `ExtensionHostAdapter::query_mam` (not only inside guest `tools.rs`) alongside post-read `archive_still_authorized` checks on every tool round; remove cross-room MAM, 1:1 DM (`conversation`), roster and presence tools per [#2030](https://github.com/waddle-social/waddle/issues/2030), and keep out-of-band MCP agents isolated on `bots.<domain>` per [#2025](https://github.com/waddle-social/waddle/issues/2025) and [#2026](https://github.com/waddle-social/waddle/issues/2026). Disallow `"private"` output mode for member-funded room `/ai` where room disclosure is required. Remove premature client-side public prompt broadcasts in Web (`extension-launcher.ts`) and Android (`ExtensionCommandController.kt`), align Apple and Linux `/ai` handling, and emit room-visible prompt/provider/payer disclosure **server-side after broker admission succeeds and before outbound provider bytes are sent**. Allow admins to select only qualified routes with verified no-training and zero-retention terms (`data_collection: "deny"`, `zdr: true`) for the exact provider, tier, endpoint, model and downstream routing; personal keys that cannot establish those terms are ineligible. Fail closed on unknown route, fallback or expired qualification. Gate unattended `jev-judgments` separately on explicit per-space tenant authorization and privacy notice requirements ([#2027](https://github.com/waddle-social/waddle/issues/2027), [#2029](https://github.com/waddle-social/waddle/issues/2029)).

8. **Canary, review and expand.** Ship trait abstractions, additive schemas, OpenFGA/Turso + Postgres/SpiceDB contract suites, broker infrastructure and denied-by-default controls first. Enable tenant-funded inference on `Turso + OpenFGA` for one test tenant with synthetic credentials, then a small curated cohort. Enable member-funded inference only after independent IdP/device-key intent, pinned broker-key distribution, provider qualification and revocation gates pass. Exercise dedicated cell placement with the same binaries. Record OTel metrics strictly using closed `MetricAttribute` enums (`server/crates/waddle-xmpp/src/telemetry/attributes.rs`—never raw `tenant_id` or JID labels), attributing per-tenant latency, throttles, cutoff times, ledger ambiguity, canceled streams and spend through structured logs/spans and durable ledger queries without prompts, responses, tokens or ciphertext envelopes. Roll back by closing admission, canceling or draining streams and disabling the feature or provider profile while preserving fences, destruction records and replay history. Never restore an old plaintext credential or remove a fence to recover availability.

## Release evidence

Each numbered step can land in one or more reviewable PRs. Dependencies follow the numbering, except trait-scoped handles and broker infrastructure can proceed in parallel after the Step 1 spike. Gate integration on all of the following:

- **Backend trait parity and tenant isolation**: Shared behavioral test suites pass against both `(Turso + OpenFGA)` and `(Postgres + SpiceDB)`. Two tenants reuse the same local account label (`alice`) and the same federated remote participant (`bob@remote.example`) without cross-tenant reads, writes, `auth_identities` collisions, OpenFGA cross-store access, cache hits, actor delivery or credential use. Saturating one tenant's CPU, Wasm memory/fuel, DB handles or streams meets the other tenant's measured service budget within `RLIMIT_NOFILE` and pod memory limits.
- **Deterministic fencing and single dispatch**: Two broker replicas racing a command (or racing across lease transfer on sharded Turso) cause at most one provider dispatch. Deterministic barrier tests cover concurrent credential revocation, room kick/policy restriction during an in-flight `OpenFGA`/`SpiceDB` check, key rotation, lease expiry, same-role holder replacement, XEP-0198 reconnect replay, uncertain provider acceptance (`unknown_after_send` quarantined with zero re-billing) and process restart, verifying both provider observations and durable ledger state.
- **Authority and boundary denials**: A guest requesting another user's key, an observer presenting a member reference, a federated remote principal, a native SCRAM account attempting member-funded enrollment, a cell attempting to write `module:<store_id>|inference` tuples in OpenFGA or forge a member/admin proof without an IdP signature, a cell substituting an unsigned broker key, and a stale holder claiming the new generation all receive denials. An independently authorized command succeeds only within its signed budget, room and scope.
- **End-to-end guest migration and zero-leak scans**: Both `ai-chatbot` and `jev-judgments` run end to end against a synthetic streaming provider without `outbound.http.request` or `configSecretFiles` secrets. Confirm bounded first-chunk latency and linear memory, synchronous `Drop` cancellation propagation across broker replicas, host-enforced `source_room` MAM bounds, server-emitted post-admission room disclosure (with no premature client prompt broadcast on denial), stripped IQ error bounces, XEP-0198 `localStorage`/`sm_unacked` secret-freedom, no direct cell route to provider hosts, and revoked legacy keys. Inspect synthetic sentinel values across cells, guests, stored configs, OpenFGA/SpiceDB tuples, archives, `sm_unacked`, traces, pod stderr and controlled memory captures (noting negative scans cover tested paths only).
- **Restore and outage resilience**: Restore older Turso `.db`/WAL and PostgreSQL/OpenFGA backups in isolation and verify that retired accounts, KMS-destroyed user keys, closed consent, stale leases and consumed nonces remain unusable before enabling egress. Exercise KMS, OpenFGA/SpiceDB, placement and broker outages plus `WADDLE_DRAIN_TIMEOUT_SECS` pod drain during active streams. Record actual measurements and residual in-flight billing risk, and complete an independent adversarial review of the final authority paths, trait implementations, migrations and rollout evidence before enabling member-funded credentials.
