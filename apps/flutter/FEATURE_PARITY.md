# Flutter client feature coverage

The Android and Wayland builds use the same Flutter screens and Rust XMPP dispatcher. The Flutter web build uses the corresponding WASM client. The comparison below uses the Waddle web chat, Apple, Kotlin Android and GTK Linux clients at revision `2f4b5240b`.

| Workflow | Flutter behavior | Verification |
| --- | --- | --- |
| Sign in and switch accounts | Device-flow sign-in, custom servers, secure credentials and per-account preferences, drafts, outbox and push identity. The server origin and bare JID identify an account. | Android Keystore and Linux Secret Service integration tests. Session and restoration tests exercise switching and stale notifications. |
| Chat and catch up | Direct messages, group DMs, rooms, unread inbox, search, nested threads, Jev scores, mentions, corrections, reactions, pins, moderation, read markers and retryable sends. Chat and Social timeline order are available in Settings. | Two native runtime clients on separate accounts exchanged messages in both directions and retrieved the messages from their archives on current main. Widget and runtime tests exercise thread navigation and message actions. |
| Files, images and stickers | Encrypted uploads and downloads, image pasting, previews, GIFs, stickers and desktop file drops. Community feed pictures and story media use public upload links. | File tests exercise authentication, limits, account changes, retry and cleanup. Desktop drop tests cover view changes during file selection. |
| Presence and profiles | Account-wide availability, manual overrides, automatic idle status, avatar, vCard, mood, activity and tune. | Status publication and parsing tests for native and WASM, plus Flutter activity, session and settings tests. |
| Feed and stories | Post text, links and pictures. Browse per-author image and video stories, play or pause, navigate by keyboard or swipe, react and synchronize read state. Record media or select a file when composing a story. | Against current main, the packaged client published and retrieved a feed entry and a story and read back a story reaction. On Wayland the packaged recorder produced an MP4 with video and audio. |
| Calendar and trips | Browse dates and recurring events, RSVP, edit or cancel an occurrence or series. Open or create a planning room, manage tasks, itinerary, travel, expenses, links, decisions, attendance and polls. | Against current main, the packaged client created an event, RSVP’d, retrieved it and removed it. It created a persistent private planning room, published a task, retrieved it and removed it. Calendar and voting UI have separate tests. |
| Administration and extensions | Owners manage spaces, rooms, roles and occupants. Rooms expose discovered extension commands, forms, list and gallery views, and their signed actions. | The packaged client listed users, created a space and room, enumerated them and deleted them against current main. UI tests also cover access checks, pagination and delete confirmation. |
| Calls | Direct and group call controls, camera and microphone selection, screen sharing, active speaker and gallery layouts, pinning and local preview. Android uses MediaProjection. Wayland uses the ScreenCast portal and PipeWire. | Android 15 and an isolated Wayland session produced video frames. The Android test exercises system-initiated revocation. A second participant decoded the Wayland presentation through a local LiveKit server. Stopping capture released the portal session before app exit. |
| Notifications | While connected, Wayland delivers desktop actions for messages and calls. Android supports notification actions, UnifiedPush, an optional Firebase Cloud Messaging build and an optional foreground connection. The browser supports Web Push. | Owner and routing tests cover account switches, cold-start actions, background replies, duplicate delivery and stale endpoints. Linux D-Bus tests cover activation tokens and notification actions. Delivery through a deployed distributor is a separate check. |

## Verification boundaries

The Linux release is an x86_64 Nix-built bundle. It uses host desktop services for key storage, notifications, audio and portal permissions. The Android preview APK includes arm64 and x86_64 libraries. Its signing key is for preview upgrades. Interoperability tests used a disposable server and accounts on loopback.

The browser chat's camera background blur and custom background images have no verified equivalent in the Flutter clients. Physical Android hardware, a deployed push service and the complete Apple, Kotlin and GTK workflows have not been exercised side by side. The calendar server records RSVPs for a series as a whole.
