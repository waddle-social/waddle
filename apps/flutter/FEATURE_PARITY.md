# Flutter client feature coverage

The Android and Wayland builds use the same Flutter screens and Rust XMPP dispatcher. The Flutter web build uses the corresponding WASM client. The comparison below uses the Waddle web chat, Apple, Kotlin Android and GTK Linux clients at revision `2f4b5240b`.

The sign-in screen, home dashboard and conversation layout follow the Polar Huddle web client at `6ccec0851`. Wide windows keep the account sidebar visible while a room is open. On narrow screens, the sidebar and conversation each have their own view. Widget tests cover room drafts across resizes, keyboard navigation, Night and Daylight themes, and layouts as narrow as 320 logical pixels with double-size text.

## Verification boundaries

The Linux release is an x86_64 Nix-built bundle. It uses host desktop services for key storage, notifications, audio and portal permissions. The Android preview APK includes arm64 and x86_64 libraries. Its signing key is for preview upgrades. Interoperability tests used a disposable server and accounts on loopback.

Android and Wayland run RNNoise and DTLN locally on outgoing microphone audio. Each channel has independent filter history. On Wayland, a second call participant received quieter fan noise with both models, decoded speech after unmuting, and heard only the selected input after a microphone switch. The publication ID stayed the same. On Android 15, two WebRTC peers transmitted and decoded synthetic PCM injected into the capture callback in a debug build. Receiver RMS fell from 0.607 with filtering off to 0.0021 with RNNoise and 0.0212 with DTLN. At 48 kHz, 12,000 warmed mono and stereo callbacks on the test host completed inside their 10 ms audio deadline. The offline tests compare both models with the web client’s reference waveforms. Device microphone performance varies with the CPU and sample rate.

Live calendar subscriptions require a server with the calendar commands. An external calendar reads the feed anonymously using the private URL and sees published changes on its next refresh. Revocation invalidates the URL for all calendar apps that use that account’s link. URLs issued by the older, deployment-wide token scheme must be replaced. The calendar server records RSVPs for a series as a whole.

Device checks used Android 15 emulators and isolated Wayland compositors. Physical Android hardware, delivery through a provisioned push service and side-by-side runs of every Apple, Kotlin and GTK workflow remain unverified.
